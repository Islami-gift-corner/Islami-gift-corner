# ব্যবসা ম্যানেজমেন্ট অ্যাপ (White-label)

যেকোনো প্রতিষ্ঠানের জন্য ব্যবহারযোগ্য — ইনভয়েস, স্টক, পার্টি খাতা, ব্যাংক/ঋণ, প্রফিট, SR ম্যানেজমেন্ট।
নাম, লোগো, রঙ ও Firebase প্রজেক্ট বদলালেই নতুন প্রতিষ্ঠানের অ্যাপ তৈরি — কোড বদলাতে হয় না।

## নতুন প্রতিষ্ঠানের জন্য সেটআপ (৫ ধাপ)

### ১. Firebase প্রজেক্ট বানান (প্রতিষ্ঠানপ্রতি আলাদা)
1. [Firebase Console](https://console.firebase.google.com) এ নতুন প্রজেক্ট খুলুন।
2. **Authentication → Sign-in method** এ *Email/Password* চালু করুন।
3. **Realtime Database** তৈরি করুন।
4. **Project settings → Your apps → Web app** যোগ করে config মানগুলো কপি করুন।

### ২. `.env.local` বানান
```bash
cp .env.example .env.local
```
ফাইলে প্রতিষ্ঠানের নাম, slug, মূল রঙ ও Firebase এর মান বসান।

| ভ্যারিয়েবল | কাজ |
|---|---|
| `NEXT_PUBLIC_BRAND_NAME` | লগইন/স্প্ল্যাশ, ট্যাব, ইনস্টল করা অ্যাপের নাম |
| `NEXT_PUBLIC_BRAND_SHORT_NAME` | হোম স্ক্রিনে আইকনের নিচের ছোট নাম |
| `NEXT_PUBLIC_BRAND_SLUG` | ইংরেজি ছোট হাতের নাম (ব্যাকআপ ফাইলের নামে লাগে) |
| `NEXT_PUBLIC_THEME_COLOR` | মূল রঙ — বাকি সব শেড ও ডার্ক মোড নিজে তৈরি হয় |
| `NEXT_PUBLIC_BRAND_LOGO` | ডিফল্ট লোগোর পাথ (ডিফল্ট `/logo.svg`) |
| `NEXT_PUBLIC_FIREBASE_*` | Firebase config |

### ৩. লোগো ও আইকন বদলান (`public/` ফোল্ডারে)
- `logo.svg` (অথবা PNG দিলে `NEXT_PUBLIC_BRAND_LOGO=/logo.png`) — লগইন/স্প্ল্যাশে দেখাবে
- `icon-192.png`, `icon-512.png` — ফোনে ইনস্টল করা অ্যাপের আইকন

> ইনভয়েসে যে লোগো ছাপা হয় সেটা অ্যাপের ভেতর থেকে **অ্যাডমিন → বিজনেস প্রোফাইল** এ গিয়ে আপলোড করা যায় — কোড/ফাইল বদলাতে হয় না।

### ৪. প্রথম অ্যাডমিন তৈরি
1. Firebase Console → Authentication → **Add user** (ইমেইল + পাসওয়ার্ড)। তৈরি হওয়া **UID** কপি করুন।
2. Realtime Database এ `users/<UID>` নামে নোড বানিয়ে এই মানগুলো দিন:
```json
{ "name": "অ্যাডমিনের নাম", "email": "admin@example.com", "role": "admin", "status": "active" }
```
3. লগইন করে **বিজনেস প্রোফাইল** এ নাম, মালিক, পদবি, ফোন, ঠিকানা, লোগো দিন।
   এরপর ইনভয়েস, স্টেটমেন্ট ও সাইডবারে সব জায়গায় এই তথ্য নিজে থেকে বসবে।

### ৫. চালান / ডিপ্লয় করুন
```bash
npm install
npm run dev        # লোকালে
npm run build && npm start
```
Vercel/Netlify এ ডিপ্লয় করলে `.env.local` এর সব ভ্যারিয়েবল তাদের *Environment Variables* এ দিন।

## একাধিক প্রতিষ্ঠান চালানোর নিয়ম
প্রতিটা প্রতিষ্ঠানের জন্য **আলাদা Firebase প্রজেক্ট + আলাদা ডিপ্লয়মেন্ট** (একই কোড, আলাদা env)।
এতে একজনের ডেটা আরেকজনের সাথে মিশে যাওয়ার ঝুঁকি থাকে না।

## নিরাপত্তা
- Firebase **Realtime Database Rules** অবশ্যই সেট করুন (শুধু লগইন করা ইউজার পড়তে/লিখতে পারবে, আর `users` নোডে role শুধু অ্যাডমিন বদলাতে পারবে)। রুল না দিলে ডেটা খোলা থাকে।
- `.env.local` গিট-এ কমিট হয় না (`.gitignore` এ আছে)।

## যা এখনো বাংলাদেশ-নির্ভর
মুদ্রার চিহ্ন (৳), ইনভয়েসের "In Words" (ইংরেজি শব্দে টাকা) ও বাংলা UI টেক্সট। অন্য দেশ/ভাষার জন্য লাগলে আলাদা কাজ দরকার।

## Firebase Rules
Firebase Console → Realtime Database → **Rules** ট্যাবে ফাইলের পুরো লেখা পেস্ট করে **Publish** দিন:
- দোকান/সেলসম্যান মোড (ডিফল্ট) → `database.rules.json`
- পাইকারি/SR মোড (`NEXT_PUBLIC_ENABLE_SHOPS=false`) → `database.rules.wholesale.json`

## দোকান ও সেলসম্যান সিস্টেম
- **অ্যাডমিন → দোকান**: দোকান যোগ করুন। প্রতিটা দোকানে আলাদা ড্যাশবোর্ড: লাইভ বিক্রয়, বিক্রয়ের তালিকা, পণ্য (স্বয়ংক্রিয় বারকোড + প্রিন্ট), সেলসম্যান, পার্টি খাতা।
- **সেলসম্যান** নিজের দোকানের পণ্য দেখে বিক্রি এন্ট্রি দেয় (ক্যামেরা স্ক্যান বা ম্যানুয়াল, দাম প্রতিবার নিজে লেখা যায়)। বাকি হলে নিজের পার্টি খাতায় ওঠে।
- সেলসম্যান শুধু **নিজের** বিক্রয় ও খাতা দেখতে পায় — এটা ডাটাবেস রুলস দিয়ে নিশ্চিত করা, শুধু স্ক্রিন লুকিয়ে নয়।
- সেভ হয়ে যাওয়া বিক্রয় সেলসম্যান বদলাতে/মুছতে পারে না; শুধু অ্যাডমিন বাতিল করতে পারে।
